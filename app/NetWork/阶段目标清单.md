# 第一部分：生命周期现状

## 1.1 四层结构

```text
进程 (Program)                    ← program.cs 管，结束方式 = 进程退出
 └─ 网络会话 (NetHost 静态)        ← 只有 Start，没有 Stop / Dispose
     └─ 大厅会话 (GamePrepareArgs + GameWorld)  ← 只创建一次，全程复用
         └─ 局 (Round)            ← BeginRound / EndRound，勉强成对
             └─ 帧 (tick)         ← 输入 → 推进 → 渲染 → [发快照]
```

## 1.2 对象生 / 死对照

| 对象 | 创建点 | 销毁/重置点 | 状态 |
| --- | --- | --- | --- |
| GameState(GameStates) | program.cs:8 | 无 | 进程级，正常 |
| GameSettings | GameSettingLoader.Load() | 无 | 进程级，正常 |
| MqttTransport | NetHost.RunAsync:36 | **从不 Dispose** | ❌ 只生不死 |

| Player(local) | 登录时 | 无 | 被局内改名污染 |
| Player(guest) | LocalDoubleSystem:17-18 | 下一局 Restart 才清 | 局后残留 |

## 1.3 八个混乱点（L1–L8）

| ID | 混乱点 | 证据 | 后果 |
| --- | --- | --- | --- |
| L1 | 网络会话与游戏会话不对齐 | 连接在 program.cs:13，pump 在 Game.Args.cs:47 启动 | 大厅/结算仍广播旧局；退出不关连接 |
| L2 | 后台任务无主 | NetHost.cs:28 _ = sp.RunAsync() | 异常静默、任务永不取消 |
| L3 | 局 Begin/End 不对称 | Game.Args.cs:50 清世界+订阅；:59 只解绑 | 局后 players 残留、广播不停 |
| L4 | 世界复用但复位不全 | GameWorld.cs:20 new Random(timeLose.Milliseconds)；LocalDoubleSystem:26 改名 | 食物序列固定；单人显示“玩家1” |
| L5 | 静态状态无重置 | NetHost.cs:18-21 四个静态；Game.RegisterInterface.cs:11 | 换房/重连/换账号全串 |
| L6 | 输入/渲染争 Console | NetHost.cs:144 Drain 读键；Client 循环无出口 | 吞按键、Esc 退不出 |
| L7 | 退出无统一 Shutdown | 全项目无 finally、无 Dispose 调用 | 端口/任务/光标残留 |
| L8 | 登录绑死在进程 | IsSetPlayerName 静态 true 后不复位 | 二次登录不生效 |

## 1.4 目标生命周期模型

```text
Session（网络）
  StartAsync: 连接 → 订阅 noLocal → 建 inbox
  StopAsync : cancel → DisconnectAsync → Dispose
       │
Broadcast（广播）
  Start(world) / Stop()   ← 由 Round 控制，不由大厅构造触发
       │
Lobby（大厅）
  new GamePrepareArgs（GameWorld + controllers）
  Dispose: 解绑所有事件、清世界
       │
Round（局）
  BeginRound: Restart → 建玩家 → 订阅事件 → Broadcast.Start
  EndRound  : 解绑事件 → Broadcast.Stop → 清世界
```

**三条原则**：谁创建谁停止；Begin 做的事 End 全撤；静态状态改实例或提供 Reset。

## 2.2 P0 详情

### P0-1 快照泵与游戏循环抢同一个 GameWorld

- 证据：SnapShotPump.RunAsync 在线程池定时器上调 world.Snapshot()；主线程同时 Snake.Add / RemoveAt / players.Clear；全项目 0 个 lock。
- 影响：偶发 Collection was modified 崩溃；更常见是撕裂快照。
- 修复（推荐 A）：A. 删后台定时器，改在游戏循环每 tick 调 NetHost.PublishSnapshotAsync(world)；B. 保留线程 + 给 GameWorld 加 SyncRoot 锁。

### P0-2 主机收自己的广播，单人模式又不消费

- 证据：订阅 snake/{room}/#，自己发的 /state 会回投（noLocal 未开）；只有 LocalDoubleSystem.cs:41 调 PumpInput，单人 FuncSystem 从不调；inbox 无上限。
- 影响：主机单人玩 10 分钟内存涨几十 MB。
- 修复：订阅 noLocal: true；单人补 PumpInput；inbox 上限 256。

### P0-3 网络消息解析没有保护

- 证据：NetHost.cs:128、:138 直接 Parser.ParseFrom(payload)，无 try/catch、无大小限制。
- 影响：同房间任何人发乱码 → 客户端/主机未处理异常退出。
- 修复：统一 TryParse（64KB 上限 + try/catch + 丢弃日志）。

### P0-4 快照尺寸不校验

- 证据：ProtoCodec.FromProtoState 原样使用 s.Width/s.Height；View.cs:20 new StringBuilder(ws.Width * ws.Height)。
- 影响：width=-1 崩溃；width=100000 OOM。
- 修复：宽高 5..200；玩家 ≤ 8；食物 ≤ 2000；单蛇 ≤ 5000 节；越界丢帧。

### P0-5 积压快照全画一遍

- 证据：NetHost.cs:134-142 对每条 /state 都 RemoteRender.Draw（内部 Console.Clear）。
- 影响：抖动积压 20 帧 → 连刷 20 次屏。
- 修复：只保留最新一帧再画。

# 第三部分：全面解决方案

## M1 生命周期收口（先立骨架，不改玩法）

```csharp
public static class NetHost
{
    static MqttTransport? transport;
    static NetOptions? options;
    static CancellationTokenSource? cts;

    public static async Task<bool> StartAsync(NetOptions o)
    {
        options = o;
        cts = new CancellationTokenSource();
        transport = new MqttTransport($"{o.Room}-{Guid.NewGuid():N}"[..18]);
        transport.Log = Console.WriteLine;              // P1-3
        if (!await transport.ConnectAsync(o.BrokerHost, o.BrokerPort)) return false;
        await transport.SubscribeAsync(default, $"snake/{o.Room}/#");
        return true;
    }

    public static async Task StopAsync()
    {
        cts?.Cancel();
        if (transport is not null) await transport.DisposeAsync();
        transport = null; options = null; cts?.Dispose(); cts = null;
    }
}
```

program.cs 用 try/finally 收口：

```csharp
try
{
    while (gameRunningState.GameRunningState is GameState.GameOnAndOffState.GameOn)
    {
        await GameRegisterSystem.UseRegister();
        await HomeScreen.ScreenFuncSystem(gameRunningState, gameSettings);
    }
}
finally { await NetHost.StopAsync(); Console.ResetColor(); }
```

Round 对称：BeginRound 里 Broadcast.Start，EndRound 里 Broadcast.Stop + 清世界。

**验收**：正常/异常退出都不留 MQTT 连接；回菜单后观战端不再收新帧。

## M2 修 5 个 P0（阶段 3 联调前必须）

1. P0-1：删 SnapshotPump 后台定时器 → 每 tick await NetHost.PublishSnapshotAsync(world)。
2. P0-2：SubscribeAsync 支持 noLocal；FuncSystem 补 PumpInput()；inbox 上限 256。
3. P0-3：统一 TryParse（大小上限 + try/catch），Drain/PumpInput 全走它。
4. P0-4：FromProtoState 校验宽高/数量，改 bool TryFromProtoState(...)。
5. P0-5：Drain 只渲染最后一条 /state。

**验收**：双终端跑 5 分钟，客户端不崩、不 OOM、不刷屏；主机单人内存稳定。

## M3 输入链路（阶段 4）

1. P1-1：RemoteInput 校验 RoomId + PlayerId，client_tick 去重；
2. P1-2：客户端补 WASD/E，填 ClientTick；
3. P1-4：Drain 不读键盘，客户端 q 退出；
4. P1-5：输入 QoS1，快照 QoS0。

**验收**：观战端 WASD 控制玩家2；连按不回退。

## M4 资源与异常（阶段 6/7）

1. P1-6：DisposeAsync 正常路径也 client.Dispose()；StopAsync 调用；
2. P1-7：泵任务持有 CTS，try/catch/finally 记日志；
3. P1-8：连接失败直接退出；
4. 断线重连：DisconnectedAsync 指数退避 + 重订阅。

## M5 安全与体验（阶段 7）

随机房号 + 字符校验；可选账号密码/TLS；日志入队；快照复用；停播；字符宽度；顺带 L4（Random 种子、名字污染）与 L8（登录静态）。
